# 实现说明：实时交互 v2

## 前台：默认一次，复杂时两次

默认直接读取已有画像、近期对话、用户纠正与相关记忆，由 `respond` 在一次生成中理解当前关切、选择支持方式、自查并输出纯文本。`CloudLLM.stream` 转发真实上游 SSE content delta；不会把完整回复伪装成打字动画，不转发 reasoning_content。

本地路由判断明确深入请求、超过 600 字的输入与配置内的风险词；也支持用户点击「深入聊聊」或传 processing_mode=deep。复杂路径以一次 `prepare` 合并当前心理分析和双视角策略，随后一次 `respond`。心理假设仍须原文证据，不合格时回退未知；前台不写长期画像。

新流程不再独立调用 analysis/planning/generation/review 四个阶段。后台 analysis 仍使用证据校验。旧版组件保留供离线对照，不在实时主流程执行。复杂 prepare 格式错误不做额外修复调用；传输前的限流/网络错误仍有有界重试，阶段数与实际 HTTP 请求数分别记录。

## 流式协议、保存与重试

`POST /v1/sessions/{id}/messages/stream` 接收 content、request_id、可选 processing_mode（auto/fast/deep）。事件按 meta → delta* → done 返回；错误为 error，等待期间有 ping。done 才表示消息事务提交成功。原 JSON messages 接口仍可用，复用同一流程但收集完整结果。

消息与幂等结果只在完整生成并通过长度、问题数量等代码检查后一次保存。断流或用户断开时取消生成，不保存半轮数据。网络可能在服务端提交后、客户端收到 done 前断开，因此界面标记“未确认保存”；以相同 request_id 重试会读取已保存结果，不重复生成。

前端通过 Fetch ReadableStream 解码 SSE，在片段到达时直接更新气泡。未完成片段不提供反馈按钮；重试替换旧片段。并发操作使用用户锁，后台远端等待不持有该锁。SSE 用有界队列背压，连接关闭会取消生产任务并关闭上游流。

trace 保存 route、foreground_calls、http_requests、ttft_ms、elapsed_ms、提示词版本及用量。ttft 从服务端开始处理计时，含用户锁等待，不含客户端网络延迟。流式 token 用量未上报时明确记录 usage_reported=false。

## 后台：按需、合并、持久化

前台成功事务同时把需要的建模任务写入 model_jobs，不等待模型执行。触发条件为显式新信息或纠正、每 BACKGROUND_INTERVAL 轮（默认 4）及 /consolidate 结束会话接口；小程序开启新会话时为旧的云端会话提交整理请求。关闭长期记忆、演示会话与已识别的紧急路径不创建普通画像任务。

同一会话尚未运行的任务合并到最新消息；相同已完成截止点不重复建模。全局最多 128 个待处理任务。启动后自动运行单个后台执行器，未完成任务可在重启后恢复。失败记录错误码，不影响成功聊天，不无界重试；后续触发可再次整理。

后台使用独立 HTTP client 与并发闸门，不抢占前台本地连接槽。但供应商账号的共享额度、上游排队或限流仍可能影响实时性。

每个任务在短锁内读取带截止消息的快照，释放锁后调用 analysis；校验原文、消息角色、深层画像门槛后，再短锁提交。摘要也在后台运行，保留已有摘要并合并真实来源，只在积累足够新内容时触发。摘要不作为画像证据。

## 纠正与删除竞态

users.memory_revision 是用户操作世代号。画像确认/纠正/撤回、记忆开关、会话删除均提升世代并取消旧任务；明确的聊天纠正也会在该轮提交时提升世代。任务提交前必须仍为 running、记忆开启、用户与会话存在，且世代匹配，否则丢弃结果。

删除用户会级联删除任务；删除会话也取消可能引用它的其他会话任务，并清理派生快照。取消不能撤回已经发送至云端的数据，但过期任务不会再产生新的画像写入。任务只保存 ID、状态和用量，不另存一份对话上下文。

五层画像仍以真实 user 原文为证据，Cognition/Regulation/Core 至少 3 条消息、2 个会话；这是工程门槛，不是校准概率。相同结论追加证据，不重复造标签；用户确认结论优先，撤回结论不自动重建。尚未实现校准后的贝叶斯更新或自动时间衰减。

## 配置与边界

运行时读取 .env、persona.yaml 和 defe.yaml。新增 RESPOND/PREPARE 模型路由；RESPOND 未填写时兼容回退旧 GENERATION 路由，最后用 LLM_MODEL。所有模型请求仍是云端 Chat Completions。可通过 LLM_EXTRA_BODY 设置供应商特有的非思考参数；默认不预设厂商。

SQLite schema 自动迁到 v4（v2 增加世代与任务表，v3 增加书店场景事件表，v4 增加 Mem0 同步、索引来源与索引世代表），不清空原会话。保持单进程、单 worker。Cookie 匿名身份、同源防护、数据隔离、参数化 SQL、证据纠正和删除范围沿用原版。

快速路径的语义检查为模型生成时自查，程序只补充可确定的约束；已显示的文本没有独立模型事前审核，不能声称安全效果等同旧四阶段流程。路由是轻量启发式，可能误判；复杂/风险场景仍需持续盲测。后台画像最终一致，用户可能在整理完成前暂时看到旧画像。

所有测试使用显式 fixture/HTTP mock，不调用真实云端。真实 API 留空时无法验证实际首字时延、总耗时、情感质量或费用；没有承诺具体秒数。

长期记忆实现现采用 Mem0 OSS，短期窗口与画像证据规则保留；完整结构、云端 Embedding 配置与迁移说明见 [memory.md](memory.md)。
